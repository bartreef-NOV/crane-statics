# Excel Validation Workbook Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate a plain `.xlsx` template, prefilled with the 22689 example, that reproduces the Scene view's hoist rope tensions and main support reactions (in-plane and out-of-plane) with live formulas.

**Architecture:** A dev-only generator package `scripts/excel_workbook/` writes the workbook with openpyxl. Inputs are the app's already-expanded model (from `normalize_document`); calculation sheets are formulas. A pure-Python recalculation helper evaluates the workbook so pytest can compare it with the app on four generated 22689 cases. The generator never ships in the app and `src/` is untouched.

**Tech Stack:** Python 3.11, openpyxl (write), `formulas` (recalculate), pytest, existing `crane_statics` calculation modules.

**Spec:** `docs/superpowers/specs/2026-10-25-excel-validation-workbook-design.md`

## Global Constraints

- Plain `.xlsx`, no macros; Excel 2016 or later; no dynamic-array functions (matrix blocks must work as ordinary or legacy array formulas).
- Units: tonnes, kN, m, kNm; gravity taken from the input.
- Single linear solve with the actual loads, not the app's baseline-plus-sensitivity decomposition; results must be identical.
- Fixed topology: boom, rear leg, front leg, platform; the solver's fixed node names.
- Every variable-length list is a fixed-size table with an `Active` (1/0) column.
- Name-based solver rules (a node id containing "winch", the `boom_hoist` rope) become explicit input columns (rope role fixed/solve, "spool node" flag).
- Acceptance: four generated 22689 cases agree with the app within 0.01 kN (forces) and 0.01 kNm (moments).
- Out of scope: load chart, Auto capacity, utilisation/limits, free-body view, Load Overview, arrow scaling.
- The source code wins over the survey in the spec; report any contradiction.
- Do not commit unrelated working-tree changes; stage only files named in each task.

## Review Focus

- Spare rows left inactive (all zeros, blank ids) must not change any result or produce `#DIV/0!`.
- More active rows than the table holds must trip a visible overflow check, not silently drop rows.
- Singular 3x3 or 6x6 matrix must show an explicit flag, not propagate `#VALUE!` through every result.
- Wind direction in each of the four directions, and wind speed 0, must give the app's sign and zero result.
- Boom angle at its extremes and a zero-length rope segment must not divide by zero.
- A hoist that is idle (zero hook load) or has no active segments must report zero tension, not an error.

## File Structure

- `scripts/excel_workbook/__init__.py`: package marker.
- `scripts/excel_workbook/recalc.py`: evaluate a workbook headlessly.
- `scripts/excel_workbook/reference.py`: expanded-model extraction and app reference results for the four cases.
- `scripts/excel_workbook/layout.py`: table sizes and cell addresses shared by writer and tests (one source of truth).
- `scripts/excel_workbook/build.py`: writes the workbook (`main()` is the CLI).
- `tests/test_excel_workbook.py`: all workbook tests.
- `tests/golden/22689_workbook_cases.json`: app reference results, generated by `reference.py`.
- `docs/excel-validation-workbook.md`: user instructions.
- `pyproject.toml`: add `openpyxl`, `formulas` to the `dev` extra.
