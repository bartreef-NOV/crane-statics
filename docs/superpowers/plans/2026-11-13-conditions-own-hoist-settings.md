# Conditions Own Hoist Settings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move `daf`, `offlead_deg` and `sidelead_deg` out of the payload-hoist definition into each condition, let each condition list the hoists usable under it, and make every load-chart point name the conditions it applies to (authored schema v12 -> v13).

**Architecture:** The authored v13 document is the contract. The normalizer turns it into the runtime `CraneDocument`, where `ConditionSpec.hoists` holds each usable hoist's lead limits, optional DAF override and its contractual points for that condition; `Hoist` loses those fields. Conditions become mandatory, so every `doc.rules is None` "legacy single default condition" branch is replaced by the one general path (a rules-less condition yields exactly one analysis case from its own wind and vessel motion).

**Tech Stack:** Python, pydantic v2, PySide6/QML front end, pytest (`.venv/Scripts/python.exe -m pytest -n auto --dist loadfile`), pre-commit (black, flake8, mypy, `tests/test_architecture.py`).

**Spec:** the "Decisions" section below (user-confirmed in conversation 2026-11-13; no separate design doc).

## Decisions (user-confirmed)

1. **Conditions always required** (>= 1). `rules` is optional and independent. Without rules a condition carries `wind_speed_m_s`, `vessel_motion` and its hoist settings; the DAF is the authored constant. `environment.max_wind_speed_m_s` and top-level `vessel_motion` are removed from the authored format.
2. **Per-condition hoist entry** `conditions.<name>.hoists.<hoist_id>: {offlead_deg, sidelead_deg, daf?}`. Listing a hoist makes it usable in that condition. With rules, an omitted `daf` is derived from the standard and a given `daf` is the manual override (what `hook_daf != 1.0` is today); without rules an omitted `daf` is 1.0. `sidelead_deg` defaults to 0.0 (as today); `offlead_deg` is required.
3. **Chart points** (`load_chart` and `split.load_chart`) each get required `conditions: [<name>, ...]` (>= 1, unique, each a defined condition). A condition's chart for a hoist is the points naming it. A usable hoist with no points for the condition is a validation error.

My calls (not asked): the boom hoist `BH` cannot be listed in a condition; every payload hoist must be usable in >= 1 condition; without rules `lift` must be `onboard`; a split hoist needs split points for each condition it is usable in; schema major goes 12 -> 13 with no v12 loader (the migration script converts files).

## Global Constraints

- `AUTHORED_SCHEMA_MAJOR_VERSION = 13`, `AUTHORED_SCHEMA_VERSION = "13.0.0"`; the published file is `src/crane_statics/schemas/crane-statics-v13.schema.json`, generated by `generate_schema.py`, never hand-edited. Remove the v12 file.
- `daf >= 1`, `offlead_deg >= 0`, `sidelead_deg >= 0`, as today.
- Migrated documents must produce numerically identical analysis results (golden tests unchanged apart from fixture format).
- Layering per `tests/test_architecture.py`: no Qt in pure domain packages; presentation formatting stays in `presentation/`.
- Use `.venv/Scripts/python.exe`. Work on a branch/worktree; tasks 2-5 are one atomic switch and the suite is expected red between them (gate at Task 5).
- `examples/crane_input_22689_abs.yaml` has uncommitted user edits: Task 6 migrates it in place, preserving them; do not `git checkout` it.

## Review Focus

- A condition lists a hoist that has no chart point naming that condition -> error naming both condition and hoist.
- A chart point names an undefined condition (typo) -> error naming the point and the name.
- A condition lists `BH` or a non-existent hoist -> error.
- Rules document with `daf` omitted still yields the standard-derived DAF (ABS/DNV golden numbers unchanged after migration).
- Renaming/deleting a condition in the app updates hoist entries and chart-point tags; deleting the last condition is refused.
